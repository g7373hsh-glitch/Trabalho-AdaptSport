## Guia de fala

### Emily — abertura, problema e objetivos

Na abertura, Emily deve apresentar o AdaptSport como um projeto acadêmico de informação sobre esporte adaptado, saúde inclusiva e acessibilidade. Deve deixar claro que o site não é uma ONG registrada e não promete atendimento ou doações.

No problema, deve explicar que pessoas com deficiência encontram barreiras de informação, acesso físico, transporte e comunicação para conhecer e praticar esportes. O dado do IBGE deve ser citado com a fonte indicada no slide. Em seguida, relacionar o projeto aos ODS 3, 10 e 11.

Nos objetivos, deve destacar as dez páginas interligadas, o conteúdo confiável, a responsividade, a acessibilidade, as interações JavaScript e a documentação do processo.

### Kauã — equipe e arquitetura

Kauã deve apresentar os cinco integrantes, os RAs e a responsabilidade de cada um. Deve explicar que a divisão foi confirmada pela equipe e está registrada em `integrantes.txt`.

Na arquitetura, deve mostrar que o projeto é estático, feito com HTML5, CSS3 e JavaScript, sem framework e sem backend. Deve citar as dez páginas, a pasta `assets`, os scripts de geração e a pasta `docs`.

### Lucas Gabriel — evolução, JavaScript e testes

Lucas Gabriel deve comparar o MVP, que tinha duas páginas, com a versão atual, que possui dez páginas. Deve explicar as melhorias: formulário, mídia acessível, fontes, menu completo e documentação.

No JavaScript, deve explicar `preventDefault()`, mensagens de erro, `localStorage`, filtro de modalidades e menu mobile. Deve demonstrar que o formulário vazio apresenta erros e que um rascunho pode ser recuperado no mesmo navegador.

### Lucas Ramon — acessibilidade, CSS, GitHub e publicação

Lucas Ramon deve explicar o foco visível, o link para pular conteúdo, os rótulos dos campos, o contraste, a legenda do vídeo, a transcrição e o layout adaptado para celular.

Também deve apresentar o repositório no GitHub e abrir o site publicado no GitHub Pages: https://g7373hsh-glitch.github.io/Trabalho-AdaptSport/. Deve explicar que os commits e o fluxo de revisão devem refletir o trabalho real da equipe, sem inventar autoria.

### Gabriel — IA, orçamento, resultados e encerramento

Gabriel deve explicar que a IA foi usada como apoio à pesquisa, estruturação e revisão, mas que o site não possui uma API generativa. O guia rápido funciona por regras fixas e foi documentado para não fingir que existe um chatbot conectado.

No orçamento, deve apresentar o GitHub Pages como a hospedagem usada pelo projeto, com custo base zero no cenário adotado. A URL pública confirmada é https://g7373hsh-glitch.github.io/Trabalho-AdaptSport/

No encerramento, deve apresentar os objetivos alcançados, os itens ainda pendentes e os aprendizados. Depois, deve chamar a demonstração técnica e abrir para perguntas.
