# Guia de versionamento e publicação

Este projeto não veio com `.git`, repositório remoto ou URL. Os passos abaixo são instruções para a equipe executar na conta que escolher. Não foram criados commits ou publicado um site nesta versão.

## Fluxo recomendado para a equipe

1. A equipe confirma quem será responsável pelo repositório e se ele será público ou se o professor terá acesso.
2. Criar um repositório chamado `adaptsport` e enviar os arquivos finais da pasta do projeto.
3. Cada integrante configura seu próprio nome/e-mail no Git e registra alterações reais com mensagens descritivas. Não atribuir autoria a outra pessoa nem dividir commits artificialmente.
4. Para uma melhoria, criar branch, por exemplo `feat/acessibilidade`, implementar a mudança, testar, abrir pull request para `main` e registrar revisão.
5. Em **Settings → Pages**, escolher a branch `main` e a raiz do projeto como fonte, se o formato de publicação oferecido estiver disponível para o repositório.
6. Aguardar o deploy e abrir a URL `https://<usuario>.github.io/<repositorio>/`. Substituir o texto em `url-site.txt` apenas pelo endereço público confirmado.
7. Confirmar HTTPS, navegar pelas dez páginas e conferir recursos, links, vídeo local e formulário no site publicado. A função do formulário permanece local e não envia mensagens.
8. Atualizar `repositorio.txt`, README, slides e documentação somente com URLs reais.

A página oficial do GitHub Pages descreve a publicação de arquivos HTML, CSS e JavaScript diretamente do repositório e informa os formatos de site de usuário/organização e de projeto. Verifique limites e condições atualizados na fonte oficial antes de publicar.
